**Create `github_issues_reader.py`** with a single public function `fetch_issue_submissions(conn)` that:

1. Uses the GitHub REST API (public endpoint, no auth needed for public repos):
   - `https://api.github.com/repos/waltaaaa/ai-newsletter/issues?labels=missing-project&state=open&per_page=100`
   - `https://api.github.com/repos/waltaaaa/ai-newsletter/issues?labels=project-correction&state=open&per_page=100`
   - Set User-Agent header: `CAN-Macro-Dashboard/1.0`

2. Track processed issues via dashboard_state key `github_issues_last_id`. On each run:
   - Read the last processed issue number from dashboard_state
   - Only process issues with number > last_processed (issues have monotonically increasing numbers)
   - After processing, update to the highest issue number seen

3. Parse issue body to extract structured fields. GitHub issue templates with YAML forms produce a body format like:
   ```
   ### Project Name

   Trans Mountain Pipeline Expansion

   ### Province / Territory

   Alberta

   ### Sector

   Oil & Gas
   ```
   Parse by splitting on `### ` headers and extracting the text below each.

4. For each new missing-project issue:
   - Call db.save_missed_project(conn, {...}) with fields mapped from parsed body
   - Set submitted_at to the issue's created_at timestamp
   - Set data field to JSON with issue number, URL, and any extra info
   - Skip issues where Source URL field is empty (matches URL hard gate)

5. For each new project-correction issue:
   - Call db.save_missed_project(conn, {...}) with type='correction' in the data field
   - Include project_name, field_to_correct, new_value, source_url, notes in the data dict

6. After processing, close each issue with a comment thanking the submitter:
   - Use GITHUB_TOKEN env var (available in GitHub Actions by default)
   - If GITHUB_TOKEN is not set (local runs), skip closing — just process
   - Comment: "Thanks for the submission! This project has been added to the processing queue."
   - Close the issue via PATCH to issues/{number} with state=closed

7. Wrap all HTTP calls in try/except. On failure, log warning and return {"skipped": True, "reason": "GitHub API unreachable: {error}"}. Pipeline must never crash.

8. Return summary dict: {"processed": N, "new_projects": M, "corrections": C, "skipped_no_url": S}

Use urllib.request (stdlib) for HTTP — no new dependencies.

```python
# ── STEP 2J: Read GitHub Issues submissions ──────────
try:
    from github_issues_reader import fetch_issue_submissions
    issues_result = fetch_issue_submissions(conn)
    if issues_result.get("skipped"):
        print(f"  [ISSUES] Skipped: {issues_result.get('reason', 'unknown')}")
    elif issues_result.get("processed", 0) > 0:
        print(f"  [ISSUES] {issues_result['processed']} new submissions "
              f"({issues_result.get('new_projects', 0)} projects, "
              f"{issues_result.get('corrections', 0)} corrections)")
    else:
        print("  [ISSUES] No new submissions")
except Exception as e:
    print(f"  [ISSUES] Warning: {e}")
```

This step reads new submissions from GitHub Issues and saves them as pending entries in missed_projects table. The existing STEP 2K (process_pending_submissions) then picks them up and runs enrichment.
