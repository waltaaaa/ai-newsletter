  <action>
  Create db.py as the single SQLite interface module. Map all 14 Firestore collections to SQLite tables:

  1. `projects` — main table with all fields from pipeline_config.make_project(). Store evidence, discovery_sources, statusHistory, sources, tags as JSON text columns. Add norm_key column (unique index). Add created/lastSeen/lastUpdated date columns.
  2. `projects_fts` — FTS5 virtual table on (name, description, province, sector, proponent) for full-text search.
  3. `indicator_history` — time series rows with composite unique on (indicator_name, period, province). **IMPORTANT — Firestore field name mapping:** Firestore indicator documents use field names `indicator` and `date`. The SQLite columns are named `indicator_name` and `period` respectively. The `save_indicator()` function MUST accept both naming conventions — if a caller passes a dict with `indicator` key, remap it to `indicator_name`; if it passes `date`, remap to `period`. Also accept `unit`, `frequency`, `description`, `backfilled` fields (store in additional columns or a `metadata` JSON column). This ensures callers migrated in Plans 13-04 and 13-05 can pass Firestore-shaped dicts without KeyErrors.
  4. `trend_snapshots` — weekly trend data with week_of date column.
  5. `weekly_briefings` — generated briefings with sections stored as JSON.
  6. `dashboard_state` — key-value store (key TEXT PRIMARY KEY, value JSON, updated_at TEXT). Replaces multiple Firestore documents (latest_briefing, microscope_history, microscope_override, tavily_credits, follow_up_queries).
  7. `pipeline_runs` — structured run logs replacing pipeline_logging.py Firestore writes.
  8. `missed_projects` — user-submitted missing projects.
  9. `pipeline_improvements` — adaptive learning improvements from learning_store.py.
  10. `statcan_indicators` — StatCan latest indicator values.
  11. `timeseries` — commodity/market time series data.
  12. `newsletters` — legacy newsletter collection (if used).
  13. `pipeline_state` — follow-up queries and state tracking.
  14. `projects_archive` — for soft-deleted or superseded projects.

  Implementation details:
  - `DB_PATH` defaults to `dashboard.db` in the project root, configurable via `DB_PATH` env var.
  - `get_db(path=None)` returns a sqlite3.Connection with WAL mode, foreign keys ON, row_factory=sqlite3.Row.
  - `init_db(path=None)` creates all tables if not exists, creates FTS5 virtual table, returns connection.
  - All JSON columns use `json.dumps()`/`json.loads()` for serialization.
  - Use `CREATE TABLE IF NOT EXISTS` for idempotent schema creation.
  - FTS5 table: `CREATE VIRTUAL TABLE IF NOT EXISTS projects_fts USING fts5(name, description, province, sector, proponent, content=projects, content_rowid=rowid)`.
  - Add triggers to keep FTS5 in sync with projects table (INSERT, DELETE, UPDATE triggers).
