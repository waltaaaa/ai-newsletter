  <name>Task 1: Create migrate_firestore_to_sqlite.py with full collection migration and verification report</name>
  <files>migrate_firestore_to_sqlite.py</files>
  <action>
  Create a one-time migration script that:

  1. **Initializes both databases:**
     - Firebase Admin SDK (reads from Firestore via serviceAccountKey.json)
     - SQLite via `from db import init_db, upsert_project, save_indicator, save_briefing, save_dashboard_state, save_pipeline_run, save_missed_project, save_pipeline_improvement, save_trend_snapshot`

  2. **Migrates each collection** with progress output:
     - `projects` — iterate all docs, call `upsert_project()` for each. Convert Firestore Timestamp fields to ISO strings. Preserve evidence arrays, statusHistory, discovery_sources as-is (db.py serializes to JSON).
     - `indicator_history` — iterate all docs, call `save_indicator()` for each. Each doc may have subcollections or be flat rows. Note: db.py's save_indicator() auto-remaps Firestore field names (indicator->indicator_name, date->period), so pass Firestore dicts directly.
     - `trend_snapshots` — iterate all docs, call `save_trend_snapshot()`.
     - `weekly_briefings` — iterate all docs, call `save_briefing()`. Convert sections from Firestore map to JSON.
     - `dashboard_state` — iterate all docs, call `save_dashboard_state(key=doc_id, value=doc_data)`. This includes: latest_briefing, microscope_history, microscope_override, tavily_credits, follow_up_queries, and any other state docs.
     - `pipeline_runs` — iterate all docs, call `save_pipeline_run()`.
     - `missed_projects` — iterate all docs, call `save_missed_project()`.
     - `pipeline_improvements` — iterate all docs, call `save_pipeline_improvement()`.
     - `pipeline_state` — migrate as dashboard_state entries (key=doc_id like "follow_up_queries", "tavily_credits").
     - `statcan_indicators` — migrate to dashboard_state or dedicated table.
     - `timeseries` — migrate commodity/market time series.
     - `newsletters` — migrate legacy newsletters.
     - `projects_archive` — if exists, migrate archived projects.

  3. **Handles Firestore-specific types:**
     - `google.cloud.firestore_v1.base_document.DocumentSnapshot` -> dict via `.to_dict()`
     - Firestore `Timestamp` -> ISO 8601 string
     - Firestore `GeoPoint` -> dict `{lat, lng}` (if any)
     - `DatetimeWithNanoseconds` -> ISO string
     - Nested maps -> JSON strings

  4. **Prints migration report** at the end:
     ```
     === MIGRATION REPORT ===
     Collection              Firestore Docs  SQLite Rows  Match
     projects                1,234           1,234        OK
     indicator_history       5,678           5,678        OK
     ...
     === ALL COLLECTIONS MATCH ===
     ```
     Count Firestore docs via `len(list(collection.stream()))` and SQLite rows via `SELECT COUNT(*) FROM table`.

  5. **Idempotency:** Uses `upsert_project()` (which checks norm_key) for projects. Uses INSERT OR REPLACE for other tables. Running twice should produce the same row counts.

  6. **Error handling:** If a document fails to migrate, log the error and continue. Report failed documents at the end. Exit code 0 only if all counts match.

  7. **Dry-run mode:** `python migrate_firestore_to_sqlite.py --dry-run` counts Firestore documents per collection and prints the MIGRATION REPORT header with expected counts, but does NOT write to SQLite. This allows verifying the script structure and Firestore connectivity without side effects.

  Usage: `python migrate_firestore_to_sqlite.py`
  Optional: `python migrate_firestore_to_sqlite.py --dry-run` to count documents without writing.
