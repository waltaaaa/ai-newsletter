## 4. Data flow & rendering pipeline

### Initial load sequence (`renderCalendar()`)
1. Read `D.watchlist` (or `D.events` as alt) from briefing data
2. If empty, fallback to `fetchJSON('events.json')`
3. **Fetch `events_global.json` and merge** — dedup by `(date + '|' + event_name)`; new events append to `_calEvents`
4. Set `_calMonth = now.getMonth()`, `_calYear = now.getFullYear()`
5. `_calPopulateInstitutionFilter()` — build the Source dropdown
6. `_calRenderHeroStats()` — compute This Week + Next Week counts, write to `#calStatThisWeek` / `#calStatNextWeek`
7. `_calWireFilters()` — attach filter listeners once (idempotent via `_calWired` flag)
8. `renderCalendarGrid()` — draw the month view
9. `renderCalendarEvents()` — draw the first page of the paginated table

### On filter change (`_calWireFilters` listener)
1. Read current filter values from the 4 controls into `_calFilter`
2. **Reset `_calPage = 1`** (critical — otherwise you can be stranded on page 5 after filtering narrows to 2 pages)
3. Call `renderCalendarEvents()` (grid + hero unchanged)

### On pagination click (`_calGoPage(n)`)
1. `_calPage = n`
2. `renderCalendarEvents()` — `renderCalendarEvents()` clamps page to `[1, totalPages]` on render so stale values self-correct
3. `scrollIntoView` on `#calendarEvents`

### Filter logic (`_calFilterEvents()`)
Applied in order:
1. **Parse date** — `parseEvtDate(e.date)` returns a Date or null; null dates are dropped
2. **Past filter** — `d < today` dropped (today at midnight counts as upcoming)
3. **Scope filter** — if scope is `this_week` drop `d > weekFromNow`; `this_month` drop `d > monthEnd`; `next_3m` drop `d > threeMonthsFromNow`; `upcoming` passes everything
4. **Impact filter** — case-insensitive exact match on `e.impact`
5. **Institution filter** — exact match on `e.institution || e.source`
6. **Search filter** — case-insensitive substring match on `(event_name + description + institution)`
7. **Sort** — ascending by parsed date

Returns the full filtered set; pagination slicing happens inside `renderCalendarEvents()`.

## 6. Pipeline integration

### `export_events_global()` in `tools/export_dashboard.py`
- Reads `config/events_global_schedule.json`
- Validates the structure has an `events` array
- Refreshes `_meta.exported_at` (ISO timestamp) and `_meta.event_count` on every run
- Writes to `{output_dir}/events_global.json`
- Accepts `conn` parameter for signature compatibility with other exporters (unused today)
- Called from `export_all()` right after `export_events()`, wrapped in try/except so a missing config file degrades gracefully (logs a warning, skips)
- On success, appends `events_global.json` to `files_written` which shows up in `manifest.json`

### Restoration context (CAL-19 through CAL-23)
`tools/export_dashboard.py` was accidentally truncated in commit `def2ea2` (2026-04-02, "Replace Ollama/Qwen with NIM Nemotron"). The truncation cut the file at line 1160 mid-docstring, removing `export_signals` body, `export_all`, `_validate_output`, and the `__main__` CLI block. The pipeline could not import and therefore could not run. This session restored the missing functions verbatim from the prior commit `b26dc7a` (cross-checked against `.claude/worktrees/nostalgic-nightingale/tools/export_dashboard.py`) and added `export_events_global()` alongside.

**`_calc_changes()` was NOT restored.** Its removal in `def2ea2` appears intentional — the surrounding `_build_market_data_from_indicators()` was simultaneously refactored to emit plain dicts without wow/mom/yoy/52w fields. If the Markets tab expects those fields, there's a latent issue separate from the truncation. Flagged in PATCH_LOG as a follow-up area.

## 7. Editorial / data integrity rules

- **URL hard gate** (from CLAUDE.md) — every event with a source link must have a real verifiable URL. All 90 entries in `events_global.json` have `source_url` pointing at official release calendars or finance ministry pages.
- **No fabrication** — every date was verified via WebFetch/WebSearch against an official source (`federalreserve.gov`, `statspolicy.gov` OMB PFEI schedule PDF, `bea.gov`, `ecb.europa.eu`, `bankofengland.co.uk`, provincial finance ministry sites). Provincial budgets verified via news coverage citing the finance ministry / legislative record.
- **No editorializing** — event descriptions are factual: what the release is, what data it covers, scheduled time. No "important" / "critical" / "watch closely" language. Canadian watchlist descriptions from `D.watchlist` may reference pipeline project counts (e.g., "The database tracks 63 oil and gas projects") because the briefing writer agent has DB access; `events_global.json` descriptions don't because the bridge file has no pipeline state.
- **Factual pagination meta** — the section header shows exactly `"N events"` or `"N events · page X of Y"`. No "upcoming" / "critical" language in the meta.
- **Merged dedup** — if the pipeline writer agent starts adding US/European events to `D.watchlist` in the future, the merge dedup by `(date, event_name)` prevents double-counting.

## 10. Known gaps / deferred

- **Static bridge file is still static** — `config/events_global_schedule.json` is hand-curated. The weekly pipeline copies it verbatim via `export_events_global()` but does not yet refresh from source calendars. Future work: build `tools/events_global_fetcher.py` with fetcher functions for Fed FOMC, OMB PFEI PDF, ECB, BoE, and provincial ministry pages that merge into the config file with dedup before the export runs. This would let the schedule stay current without manual edits.
- **Tooltip overflow on last-row month cells** — the upward-opening tooltip can still clip above the viewport if the cell is near the top of the browser window. Deferred as future work: detect row position in JS and toggle an `.opens-down` class on last-row cells, or pin the tooltip to `position: fixed` with JS-computed coordinates.
- **Empty Canadian watchlist fallback** — if `D.watchlist` is empty and `events.json` fails to load, only the `events_global.json` bridge events render. This is acceptable (the global events are still useful) but flagged for awareness.
- **Event descriptions cross-ref** — `events_global.json` descriptions do not reference Canadian pipeline project counts, since the bridge file has no DB access. Future work in `export_events_global()` could augment descriptions with DB-derived counts (e.g., "The database tracks N construction projects that depend on March CPI").
- **`_calc_changes()` refactor** — `tools/export_dashboard.py` had `_calc_changes()` removed in the same commit that truncated the file. This session did NOT restore it (the removal appears to have been part of an intentional refactor that simplified `_build_market_data_from_indicators()`). If the Markets tab expects `weekly_pct` / `mom_pct` / `yoy_pct` / `high_52w` / `low_52w` / `direction` fields, there's a latent Markets-tab bug to investigate separately.
- **CAL_PAGE_SIZE hardcoded** — page size is a module-level `const CAL_PAGE_SIZE = 10`. If page-size should be user-configurable in the future, plumb it through a dropdown in the filter bar and update `renderCalendarEvents()` to read from state.
- **No per-institution impact overrides** — the `impact` field comes directly from the event data. If the dashboard ever needs to recompute impact based on Canadian-specific relevance (e.g., "high" for US CPI when CAD-USD is volatile), that logic would live in the pipeline or a new frontend helper.
